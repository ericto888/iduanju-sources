# 站源首页与分类导航协议（idj1）

本文定义短剧、影视等视频站源的首页分类接入方式。目标是：**主程序复用导航、分类选择、分页和加载状态；站源只提供真实栏目及其内容解析。** 不要求每个站源都拥有“推荐”“最新”或“原创短剧”。

## 1. 职责划分

### 主程序负责

- 根据 `home()` 返回的分类动态生成顶部分类导航。
- 统一处理当前分类、高亮、横向滚动居中和“全部分类”入口。
- 调用 `category({ id, page })`，展示内容并处理分页。
- 处理加载、空数据、错误和重试状态。
- 对没有提供动态分类的旧插件保留原有兼容路径。

### 站源负责

- 返回网站真实存在、当前可用的分类。
- 保持分类 ID 稳定且唯一。
- 根据分类 ID 和页码请求对应栏目。
- 解析剧集、分页信息及播放资源。
- 网站没有某个栏目时，不得伪造该栏目。

## 2. 首页接口

`home()` 返回对象，`categories` 为可选数组：

```javascript
async home() {
  return {
    categories: [
      { id: "recommend", name: "推荐" },
      { id: "latest", name: "最新" },
      { id: "original", name: "原创短剧" },
      { id: "ai", name: "AI短剧" }
    ]
  };
}
```

上面仅为结构示例。实际插件只能填写目标网站确实存在且能请求的栏目。比如某站只有“电影、电视剧、动漫”，就只返回这三个栏目。

字段约定：

| 字段 | 必需 | 说明 |
|---|---|---|
| `id` | 是 | 站源内部稳定唯一 ID；用于后续分类请求 |
| `name` | 是 | 展示给用户的真实栏目名称 |
| `isRank` | 否 | 可选榜单标记；仅在主程序相关能力支持时使用 |

不要用栏目名称作为请求参数，也不要在客户端按站源名称硬编码分类映射。

## 3. 分类接口

`category({ id, page })` 按分类 ID 和页码返回数据：

```javascript
async category({ id, page = 1 }) {
  // 根据 id 选择站点真实栏目地址，并请求第 page 页。
  // 这里的地址、解析规则由具体站源实现。
  const result = await fetchAndParseCategory(id, page);

  return {
    items: result.items,
    page,
    hasMore: result.hasMore
  };
}
```

返回字段：

- `items`：剧集数组，至少包含主程序可识别的 `id`、`title`，并尽可能提供 `cover`。
- `page`：当前页码。
- `hasMore`：是否还有下一页；必须依据真实分页信息或可靠的页数规则判断。

分页 URL、请求头、Cookie、加密参数和 HTML/API 解析均由站源处理，主程序不应了解各网站的 URL 结构。

## 4. 可选首页数据

如果网站首页有独立推荐内容，可以由 `home()` 同时返回 `items`：

```javascript
async home() {
  return {
    items: [],       // 可选：首页推荐内容
    categories: []   // 网站真实分类
  };
}
```

没有独立推荐流的站点无需提供 `items`，也不应为了填充首页而把第一个分类伪装成推荐。没有“最新”栏目就不要返回“最新”。

## 5. 兼容要求

- 旧插件继续按原有接口运行，不要求一次性迁移。
- 新插件优先实现 `home()` 与 `category()`。
- 分类 ID 发生变化时，应同步更新插件版本及相关缓存策略。
- 分类单独请求失败不应导致其他分类数据全部丢失。
- 同一分类的分页必须保持 ID 一致，且从第 1 页开始连续递增。

## 6. 接入验收清单

- [ ] `home()` 返回的栏目均真实存在。
- [ ] 每个分类 ID 唯一、稳定，名称准确。
- [ ] 每个分类第 1 页能正确解析。
- [ ] 有下一页时 `hasMore` 为 true，末页为 false。
- [ ] 第 2 页不会重复第 1 页，也不会丢失分类参数。
- [ ] 无推荐或最新栏目的站点不会显示虚构入口。
- [ ] 详情、播放、搜索等既有能力通过真机测试。

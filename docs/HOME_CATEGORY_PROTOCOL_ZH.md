# 站源首页与分类货架接入规划及测试规范（idj1）

> 本文面向站源开发者、插件维护者和 iDuanJu 客户端联调人员。
>
> 站源仓库负责定义数据协议、manifest 能力声明和验收用例；iDuanJu 主程序负责首页 UI、缓存、分页、刷新、导航及播放流程。本文列出的测试用例是验收标准，不代表已在某个版本或真机上全部执行通过。

## 1. 目标

让主动适配的 JavaScript 视频站源复用 iDuanJu 已有的红果、黄果式首页组件，同时不破坏旧插件：

- 支持可选的首页精选轮播。
- 支持按站点真实栏目生成多个横向内容货架。
- 每个货架有分类入口和「全部」列表。
- 「全部」列表默认显示普通海报网格；只有插件显式声明时才显示数字序号。
- 没有独立精选内容时，首页轮播位置使用**按站点分类顺序查找的第一个有内容的分类**作为展示来源。
- 分类货架、全部列表、分页、刷新和详情播放复用主程序现有能力，不在插件内另造一套首页缓存或分页系统。
- 未声明 `categoryShelves` 的旧插件继续走原有首页路径，不因升级客户端而自动切换到多货架首页。

## 2. 职责边界

| 模块 | 负责内容 | 不负责内容 |
|---|---|---|
| JS 站源 | 实现 `home()`、`category()`、详情和播放；返回真实分类和内容数据 | 不实现 SwiftUI 首页，不自建客户端货架/列表 UI |
| manifest | 声明 `capabilities` 和可选 `homeFeatures` | 不通过插件 ID、站点名称或 URL 推断 UI 能力 |
| iDuanJu 主程序 | 根据能力声明选择首页路径；展示精选/货架；管理 BoardCache、分页、刷新、详情路由 | 不硬编码某个站点的栏目名称、栏目 ID 或站点特例 |
| 站源目录仓库 | 维护协议、示例、开发说明和验收清单 | 不以目录 JSON 校验替代网站解析和客户端真机测试 |

## 3. manifest 能力声明

首页展示能力放在 manifest 的 `homeFeatures` 数组中。只要声明了任一首页能力，`capabilities` 就必须包含 `home`。

| 能力值 | 作用 | 未声明时 |
|---|---|---|
| `categoryShelves` | 启用红果/黄果式多分类货架首页 | 保留旧插件首页路径，不自动切换多货架 UI |
| `featured` | 允许将 `home().items` 作为首页精选轮播数据 | 不把 `home().items` 当作精选；使用第一个有内容的真实分类作为轮播展示来源 |
| `numbered` | 分类「全部」页面显示数字序号 | 普通海报网格，不显示排名数字 |

### 3.1 推荐声明

典型的多分类站源，启用精选数据和多货架，但「全部」列表不显示排名数字：

```json
{
  "capabilities": ["home", "category", "detail", "play"],
  "homeFeatures": ["categoryShelves", "featured"]
}
```

如果该站点的分类列表本身就是明确的榜单，并且希望在「全部」页面显示排名，再增加 `numbered`：

```json
{
  "capabilities": ["home", "category", "detail", "play"],
  "homeFeatures": ["categoryShelves", "featured", "numbered"]
}
```

### 3.2 能力组合规则

- `categoryShelves` 是启用新多货架首页的必要开关；单独声明 `featured` 或 `numbered` 不会让旧插件自动进入多货架首页。
- 在多货架首页中，只有同时声明 `featured` 且 `home().items` 解析出至少一条有效内容，才使用插件精选数据作为轮播。
- 声明了 `featured`，但精选数据为空、字段不完整或被内容安全过滤后没有有效条目时，轮播仍然保留：主程序按 `categories` 的顺序加载分类，选择第一个有内容的分类作为轮播内容来源。
- 未声明 `featured` 时，即使响应意外带有 `items`，也不会将其当成精选；仍按分类顺序寻找第一个有内容的分类。
- 未声明 `numbered` 时，分类「全部」页面不显示数字序号。不能根据栏目名称含「热门」「排行」、数据顺序或 `isRank` 字段擅自打开序号。
- 三项能力可组合使用；重复值和未知能力值属于 manifest 错误。
- `homeFeatures` 是 UI 能力声明，不是 JS 导出函数名，不应放进 `capabilities`。

## 4. 首页数据协议

### 4.1 `home()`

推荐返回真实分类，以及可选的精选数据：

```javascript
async home() {
  return {
    categories: [
      { id: "latest", name: "最新" },
      { id: "movie", name: "电影" },
      { id: "series", name: "电视剧" }
    ],
    items: [
      {
        id: "video-001",
        title: "首页精选示例",
        cover: "https://img.example.com/cover-001.jpg",
        remarks: "更新至 12 集"
      }
    ]
  };
}
```

字段说明：

| 字段 | 必需性 | 说明 |
|---|---|---|
| `categories` | 多货架站源应提供 | 网站真实栏目数组；每项必须有稳定唯一的 `id` 和非空 `name` |
| `items` | 可选 | 仅在声明 `featured` 时作为精选候选；每项必须有有效 `id` 和 `title`，建议提供封面 |
| `isRank` | 可选 | 栏目本身的榜单属性信息；不等于客户端数字序号开关 |

约束：

1. 分类 ID 应稳定、唯一，并直接作为后续 `category({id,page})` 的请求参数。
2. 分类名称应与目标网站实际栏目一致，不要为了填满 UI 虚构「推荐」「最新」「原创」等栏目。
3. `items` 应是可进入详情的剧集数据，不要把分类对象或无详情 ID 的占位数据放进精选。
4. 精选最多取前 5 条展示；无效条目应在客户端解析阶段被剔除。
5. 如果网站没有独立精选流，无需为了填充 `items` 而复制某个分类第一页。客户端会从真实分类中寻找第一个有内容的栏目作为轮播来源。

### 4.2 分类字段缺失与空数组

客户端必须区分以下响应：

| `home()` 响应 | 语义 | 客户端处理 |
|---|---|---|
| 有 `categories` 且非空 | 返回最新分类清单 | 更新分类缓存并按新清单展示 |
| 有 `categories: []` | 明确表示当前没有可用分类 | 清空分类缓存；多货架首页显示无可用分类状态，不生成虚构「推荐」栏目 |
| 没有 `categories` 字段 | 本次响应未提供分类信息 | 保留此前有效分类缓存，不因字段缺失清空数据 |
| `categories` 为 null 或非数组 | 分类字段格式错误 | 视为本次未提供有效分类信息，保留此前有效缓存 |
| `home()` 请求失败 | 网络或站点错误 | 保留已有缓存并展示可重试错误状态，不覆盖成空分类 |

对于未声明 `categoryShelves` 的旧插件，客户端保留原有 `__home` 兼容入口，以维持既有首页数据流。该兼容入口不是新多货架站源可以伪造的真实分类；新多货架站源不应依赖它。

## 5. 分类分页协议

`category({id,page})` 根据分类 ID 和页码返回对应栏目内容：

```javascript
async category({ id, page = 1 }) {
  const result = await fetchAndParseCategory(id, page);
  return {
    items: result.items,
    page,
    hasMore: result.hasMore
  };
}
```

- `page` 从 1 开始。
- `id` 必须用于选择对应的真实栏目，不能无视 ID 始终返回默认分类。
- `items` 每项至少包含主程序可识别的 `id`、`title)，并尽可能提供 `cover`。
- `hasMore` 必须根据真实分页信息或可靠的页数规则判断。
- 同一分类连续翻页不能重复第一页，也不能串入其他分类的数据。
- 内容 ID 应稳定，便于客户端去重、缓存和详情跳转。
- 分类请求失败应独立处理，不应导致其他分类货架全部清空。

## 6. 首页展示和交互流程

### 6.1 声明了 `categoryShelves`

1. 主程序读取 manifest 的 `homeFeatures`。
2. 调用 `home()`，更新真实分类缓存；缺少 `categories` 字段时保留旧缓存，显式空数组则清空。
3. 若声明 `featured` 且解析出有效精选条目，使用精选条目显示轮播。
4. 若没有有效精选条目，主程序按分类顺序使用现有 BoardCache 加载分类第一页，选择第一个有内容的分类作为轮播来源。前面的空分类不应阻止后续分类成为轮播来源。
5. 按真实分类生成横向内容货架；货架数据按需加载。
6. 点击货架「全部」进入对应分类的统一列表页。
7. 列表页复用主程序现有 Pager、分页、下拉刷新、海报卡片、详情和播放路由。
8. 只有声明 `numbered` 才在分类「全部」列表显示序号。
9. 切换站源后，不得把上一个站源的精选、分类或分页数据混入当前站源。

### 6.2 未声明 `categoryShelves`

- 继续使用客户端原有 JS 插件首页路径和展示行为。
- 不自动显示新的多分类货架布局。
- 不因为声明了 `featured` 或 `numbered` 就单独改变首页分流。
- 旧插件可继续使用历史 `home()` 首页数据和兼容分类入口；可逐步升级到本协议，但不要求一次性迁移。

## 7. 缓存、分页和刷新原则

- 分类元数据复用主程序现有 PluginStore 分类缓存。
- 首页货架及分类「全部」列表复用主程序现有 BoardCache / Pager，不在站源中自行维护 UI 状态。
- 同一分类的首页货架和「全部」列表应共享稳定分类 ID，但分页状态按主程序既有列表逻辑管理。
- 首页刷新时重新获取首页元数据，并刷新当前已加载的分类内容。
- 分类列表下拉刷新重新获取第一页；上拉加载下一页。
- 刷新首页分类时，如果响应缺少 `categories`，保留上次有效分类；如果显式返回空数组，则按空分类处理。
- 站源更新改变分类 ID 时，应同步更新插件版本和分类映射，避免旧 ID 被错误复用。

## 8. 测试计划与完整验收用例

测试分为三层：

1. **协议/解析单元测试**：验证 manifest、首页响应解析、有效精选过滤、分类缓存语义和序号开关。
2. **客户端 UI / 状态测试**：验证首页分流、精选回退、多货架、列表、分页、刷新和站源隔离。
3. **真实站点联调/真机验收**：验证网站接口是否仍可访问、内容是否真实、封面/详情/播放是否可用。

目录仓库的静态校验通过，不等于站源真实可用；单元测试通过也不等于网站当前接口可用。每次真实联调应记录测试日期、插件版本、设备和结果。

### B. 首页响应解析和缓存语义

| 编号 | 测试场景 | 操作/输入 | 预期结果 |
|---|---|---|---|
| HM-01 | 正常分类 | 返回多个合法分类 | 分类 ID、名称、顺序正确 |
| HM-02 | 分类重复 ID | 两项分类使用相同 ID | 去重，不生成重复货架 |
| HM-03 | 分类字段非法 | 缺少 ID 或名称 | 非法分类被剔除 |
| HM-04 | 分类字段缺失 | 响应不包含 `categories` | 不清空原有有效缓存 |

| HM-08 | 精选为空 | 声明 featured，items 为空 | 回退到第一个有内容的分类 |

| HM-12 | 首页请求失败 | 网络断开或站点返回错误 | 显示错误和重试入口，不覆盖有效分类缓存 |
| HM-13 | 空响应对象 | `home()` 返回空对象 | 不崩溃；不伪造真实栏目 |
| HM-14 | 连续进入首页 | 多次切换进入同一站源 | 不产生重复货架或无意义请求风暴 |

### E. 分页、刷新与缓存

| 编号 | 测试场景 | 操作/输入 | 预期结果 |
|---|---|---|---|
| PG-01 | 首屏 | 打开分类全部 | 请求 page=1 |
| PG-02 | 上拉分页 | 滚动到底部 | 请求 page=2，追加数据 |
| PG-03 | 连续分页 | 继续滚动到底部 | 页码递增，不重复请求同一页 |
| PG-04 | 末页 | hasMore=false | 停止请求下一页 |
| PG-05 | 第二页失败 | page=2 网络失败 | 保留已加载内容并可重试 |
| PG-06 | 列表下拉刷新 | 在分类列表下拉 | 重新加载第一页 |
| PG-07 | 首页下拉刷新 | 在多货架首页下拉 | 更新首页元数据并刷新已加载内容 |
| PG-08 | 分类缓存隔离 | 两个分类分别加载和翻页 | 分类数据、页码互不串用 |
| PG-09 | 站源缓存隔离 | A 站源切换到 B 站源 | 不显示 A 的分类、精选和内容 |
| PG-10 | 返回首页 | 从分类全部返回 | 首页货架和滚动状态符合现有缓存策略 |
| PG-11 | 重复内容 ID | 下一页返回第一页已有内容 | 按主程序去重规则处理 |
| PG-12 | 网络恢复 | 请求失败后恢复网络并重试 | 能重新加载首页或分类 |
| PG-13 | 分类字段缺失刷新 | 刷新时 home() 未返回 categories | 保留已有分类，不出现空白货架 |
| PG-14 | 显式空分类刷新 | 刷新时返回 categories=[] | 清空旧分类并展示无可用分类状态 |
